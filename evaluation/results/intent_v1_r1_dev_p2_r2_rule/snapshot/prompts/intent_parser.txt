For EVERY positively requested metric, add a fields entry in the user's order, including metrics absent from field_catalog. An absent metric is field=null, never omitted or put in excluded_fields. Preserve two separately named metrics even if one contains the other. mention is an exact contiguous original phrase: do not rewrite it into the standard field name. If the user uses a synonym, keep that synonym in mention and put the catalog name only in field. Avoid adding reporting verbs, list counts or whole sentences to a metric mention.
excluded_fields contains ONLY metrics the user explicitly withdrew or excluded. A later positive metric after a conjunction is still requested. Declining explanations affects knowledge_question only; it does not exclude a positively requested report metric. Declining a full report does not exclude the requested individual metrics.
Select requested target and comparison roles, not simply the first date mentioned. Retracted, negated and background dates need not be selected. Use absolute YYYY-MM.
For a relative TARGET declare target_anchor according to the user's intended starting point:
- previous_target: the conversation continues from the previous report's resolved target month.
- When previous_intent has a target month, a continuing relative target MUST use previous_target, unless the user explicitly chooses this turn's queried record as the starting point. Do not use current_lookup simply because it already matches the requested target.
- current_lookup: the user explicitly starts from this turn's queried record, using current_lookup_month. Do not choose it merely because a lookup already happened.
- today: an ordinary first-turn calendar-relative request with no previous target, such as 上个月/下个月, starts from today's month. The current lookup may already be that requested month; never shift the lookup again.
- none: an unknown event/start month, such as a fictional cabin opening date. If a declared anchor is absent, also return null and unresolved=true; never silently substitute another anchor.
For absolute targets or inheritance without a new relative phrase, target_anchor may be none. Relative BASELINES always start from the selected target; 环比 is one month before it. Calendar arithmetic supports N个月前, N个月之前, 之前N个月, N个月后, 上上个月, 下下个月; N may use Arabic or Chinese numerals including 两. 前N个月 is ambiguous: do not assume an offset (the ordinary phrase 前一个月 remains a one-month offset). If unclear return null and unresolved=true, never guess.
scope: only_listed for a restricted list, full_report for an entire report, otherwise unspecified. Preserve full_report scope when excluding metrics. knowledge_question is the verbatim knowledge subquestion, or empty. Exclude explicitly declined explanations. Use report_with_knowledge only when that subquestion exists. Preserve requested field order.
Requests to read recorded amounts, percentages, lifetimes or categorical levels are report requests, not knowledge questions. Instructions to copy, report or arrange a metric are never knowledge_question. Set it nonempty only for a separate requested explanation, definition, maintenance or compatibility question. Explicitly declined explanation/maintenance questions leave it empty. Current selections, cancellations and ordering override historical requests; inherit only what the current reference actually requests.
Return compact JSON with no unnecessary whitespace. Use empty strings/lists and null exactly as the schema requires.
