# 评分合同补充说明 01：相对月份的锚点

- 适用对象：`evaluation/intent_v1_r1/SCORING.md`（已冻结，本文件不修改它）
- 日期：2026-10-13，P1 代码复核后、P2 开始前，未运行任何模型
- 状态：作者提交本文件即视为批准

## 背景

冻结的 SCORING 规定：

1. 相对目标"以 previous 有效目标为锚，否则以 current 查询月为锚"；
2. 缺少 previous 目标和 current 查询月时 `unresolved_month=true`，"不得用 today 猜月"。

P1 复核发现，在报告出口这个调用位置，第 1 条会导致一个常见错误：用户首轮说"请生成我上个月的报告"时，Agent 已经按今天查了上个月的记录，若再以这个查询月为锚减一个月，就会错一个月。原规则版本在这种情况下直接返回"无法确定"。

## 补充口径

没有上一轮目标时，相对说法的锚点按用户原话判断：

| 用户的说法 | 锚点 |
| --- | --- |
| 明确以某条记录为起点（如"以刚查到的这份为起点，前一个月"） | 本轮查询月 |
| 首轮的普通相对说法（如"上个月""下个月"） | 今天所在的月份 |
| 起点是未知事件（如"搬家前一个月""第一次换刷那个月"） | 无锚点，`unresolved_month=true` |

有上一轮目标时，仍以上一轮目标为锚。

"上个月"在首轮的字面含义就是相对今天，以今天为锚是按原意解释，不属于原合同所禁止的"用 today 猜月"。原合同第 2 条仍然适用于真正没有锚点的情况。
