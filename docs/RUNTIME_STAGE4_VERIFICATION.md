# Runtime / Harness 第四步验收（2026-10-01）

本阶段已补齐故障 Harness、分层投毒评测、正常对照、检索消融及交付记录。它验证有限执行和来源边界，并保留攻击暴露后的失败；不能表述为消除了 RAG 投毒。

## 代码与环境

新增 `evaluation/harness.py`、`harness_faults.py`、`harness_attacks.py`、`security_cases_v1.json`、`normal_recheck.py`、`retrieval_ablation.py` 和 `rag/relevance.py`；入口为 `scripts/manage.py harness`。源码打包排除临时锁文件，并显式纳入本阶段检索证据。

CPython 3.12.2，沿用 121 项锁定依赖；没有新增安装包。doctor 的 139 项检查通过，pip check 无依赖冲突。聊天模型为 Qwen3:4b，temperature=0、reasoning=true、num_ctx=8192；digest 为 `359d7dd4bcdab3d86b87d73ac27966f4dbb9f5efdfcc75d34a8764a09474fae7`。正式检索使用 Qwen3-embedding:4b，digest 为 `df5bd2e3c74cd8d069d21dc038f1b359fcdc9458fce1c99bd43c9eb1518ff907`。安全合成集使用 LocalEmbeddings；不把其成绩当成正式 embedding 的召回成绩。

Harness 冻结业务、配置、提示词、资料、执行器、测试和固定安全题集。worker 执行快照；完整提交记录以 `jobs/` 为准，原子重建汇总，恢复时校验输入/参数/依赖/模型身份。异步迟到和不完整负面结果不会算作防护成功；已观察到的副作用不会因后续错误被抹去。详细命令见[第四步说明](RUNTIME_STAGE4.md)。

## 离线结果

190 项回归运行：189 通过、1 跳过。跳过项为 Windows 真实符号链接测试，当前系统没有创建权限。完整离线 Harness 记录 30 个场景，无缺失或执行错误：7 个故障场景全部断言通过，23 个安全/正常样本全部完成。离线强制越权提议验证了工具执行前拒绝和零受保护回调，不计入真实模型 ASR。

故障检查覆盖实际模型/工具阻塞、跨请求连续故障熔断、半开单探测恢复、无限工具循环、取消后迟到不得提交、容量保留及排队零执行。每个故障场景包含正常恢复对照，并检查实际 dispatch、调用预算或会话提交，不以“抛出异常”代替验证。

开发中出现过 Windows Chroma 句柄未释放和脚本模型返回空内容两类 Harness 故障，初次失败日志保留在 `evaluation/results/runtime_stage4_development/`。修复分别关闭当前合成 fixture 独有的客户端、独立记录清理状态，并修正非空脚本回答；没有为让测试通过而修改正式 RAG 回答逻辑。最终日志另存，不覆写这些失败。

## 当前仍存在的限制

获准错误事实没有可靠的真伪识别，恶意工具文本可能经直出路径污染用户可见答案；两个真实失败类别均保留。下一轮应优先设计有类型的工具返回、输出层边界和事实来源核对，并扩大攻击/正常集，避免简单规则扩大误拦截。

用户 ID 仍是本地演示数据选择，不是生产认证或多租户 ACL。同步超时只限制等待，不能保证停止远端请求；审批清单/程序/索引受保护是当前威胁假设。有限合成集、单模型和一次运行不能证明消除投毒或生产级安全。
