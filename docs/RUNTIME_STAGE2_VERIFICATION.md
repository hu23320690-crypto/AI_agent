## 故障验证证据

| 场景 | 已验证的行为 |
| --- | --- |
| 一次连接失败后成功 | 正好两次尝试，model计数为2，成功结果才提交 |
| RAG 内部模型失败后成功 | 重试内部模型；检索和工具各执行一次，总model计数4 |
| 连续失败/重试耗尽 | 不超过配置次数；异常穿透工具层，不生成伪造回答，不提交历史 |
| 配额耗尽 | 重试占用原有预算；没有余量时不再等待退避 |
| 同一逻辑调用时间不足 | 拒绝不满足剩余时间的退避，不重新获得完整调用时限 |
| 取消发生在退避中 | 不再发起第二次尝试 |
| 同步线程等待超时 | 底层可能仍在运行；不会启动重叠重试，按已派发的叶子故障计数 |
| 本地排队超时 | 不误记为依赖故障 |
| 参数/权限/404/422/本地协议错误 | 不自动重试，不计入依赖故障窗口 |
| 查无业务记录 | 正常返回，不触发熔断 |
| 未声明安全的写操作 | 默认只尝试一次；未实现写操作幂等或补偿 |
| 滚动窗口与最小样本 | 过期故障移除，最小样本和失败阈值同时成立才打开 |
| 半开并发 | 24个竞争许可请求中只有1个获准探测 |
| 半开失败/取消 | 失败重新冷却；取消释放名额而不声称恢复 |
| 迟到结果与过期许可 | 旧代次结果不能改变新状态；排队期间熔断的旧许可禁止实际派发 |
| 新 Agent 会话 | 同一执行器保存断路器状态，后续会话直接拒绝；探测成功后恢复 |
| 依赖隔离 | 一个依赖熔断不会阻止另一依赖的新任务 |
| 依赖终止与并行工具 | 立即将终止状态发布到 RunContext，其他等待方无需等待底层阻塞函数结束 |
| SDK 实际错误转换 | 真实 ChatOllama/Ollama SDK + httpx.MockTransport：HTTP 503 转 ResponseError 后重试，解析第二次流式响应成功 |
| Retry-After | 可读响应头的等待值受尊重；无法容纳该等待则结束，不提前重试 |

故障测试没有停止用户 Ollama，没有向真实服务写入故障状态，没有污染现有知识库。测试使用可释放的阻塞函数，退出前释放测试自行制造的阻塞条件。

## 限制与下一步

- 熔断和并发状态在进程内共享，重启清空，多进程之间不共享；阈值未经生产负载校准。
- 同步等待超时不是强制终止底层线程或远端推理。底层 HTTP 超时后安全重试仍可能导致远端重复计算。
- 固定 Ollama SDK 的 ResponseError 不保留 Retry-After 响应头，这种错误只能采用本地退避。
- 未提供外部写操作幂等保障、持久化任务恢复、完整生产认证。
- 第三步 RAG 来源管理/撤销/工具权限，以及第四步完整投毒评测仍待实施。
