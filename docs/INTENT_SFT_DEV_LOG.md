# 意图 SFT 开发日志（只用 dev）

按 [预注册计划](plans/INTENT_SFT_PLAN.md) 第 6 节，最多 3 轮。每轮记录数据版本、训练配置、dev 结果和失败原因。test 在冻结最终配置前不打开。

## 同机 dev 基线（qwen3:4b + 长提示词）

| 模式 | 完全正确 | p50 / p95（s） | 证据 |
| --- | ---: | --- | --- |
| llm_only | 82.5%（33/40） | 1.007 / 1.195 | `evaluation/results/intent_sft_dev_baseline_qwen3_4b_llm_only` |
| hybrid | 80.0%（32/40） | 0.999 / 1.361 | `evaluation/results/intent_sft_dev_baseline_qwen3_4b_hybrid` |

hybrid 有 1 题超时（第一次调用要加载模型，属于冷启动）。之后的 SFT 运行在评测前先预热模型。

## 第 1 轮（r1）

- 数据：`generate.py` seed 20261030，6000 条（train 5700 / val 300），全部通过 resolver 校验；构造阶段跳过 223 次，重复 11 次。
- 模型：Qwen3-1.7B，LoRA r16，1 epoch，bf16；训练 20 分钟，val loss 0.0006。
- dev：llm_only 87.5%（35/40），hybrid 87.5%（35/40）；p50 0.68s / 0.64s。

| 题 | 错误 | 原因 |
| --- | --- | --- |
| ID022、ID023 | 目标月取成了基准月（危险错误 / 安全失败） | **生成器伪相关**：比较类样本的 current_lookup_month 总等于目标月；dev 中最后一次查询是基准月 |
| ID032 | 基准月更正后漏掉 compare | 没有"不是用 X 作基准，而是 Y"这种写法 |
| ID038 | 漏判知识请求 | 只有独立问句形式的知识子问，没有"同时说明这个指标代表什么" |
| ID003 | 新改写被判为未知字段 | 改写词表是封闭的，模型倾向把词表外的说法当作未知 |

**违规记录**：r1 的部分模板句式与 dev 题面过于接近（例如"以 X 作基准，告诉我……比它变了多少""帮我做个环比；只比较这一项"），知识问句和未知指标池中也各有一条取自 dev。这违反了计划第 3 节"不复制、不改写 dev 题面"的约定，因此 r1 的 dev 成绩偏乐观，不作为任何结论。test 从未打开，不受影响。r2 会删除或改写全部此类模板。

## 第 2 轮（r2）改动

- **消除伪相关**：比较类样本的两个查询月随机排序，current_lookup_month 取最后一个；否定更正类同样处理；其余类别有 20% 的样本额外查询了另一个月。
- **删除 dev 雷同**：替换了上表所述的全部模板，删除取自 dev 的知识问句、"月度耗电量 / 耗电量"和限定词"墙角"。
- **新写法**：基准月更正（"基期不是 X 而是 Y"）；针对所选指标本身的知识请求（"顺便解释下 X 是什么含义"等，措辞与 dev ID038 不同）；多字段问句式。
- **改写词表**：用 gemma4:12b 为每个字段生成 12 个候选说法（只提供字段名和取值示例），再人工逐条筛选。凡是可能指向另一字段的（例如泛泛的"滤网"说法、"毛发缠绕情况"）、带限定词的、与 dev 雷同的，一律删除。保留后，每个字段有 1～6 个改写。
- 数据：seed 20261031，8000 条（train 7600 / val 400）。
- 说明：r1 失败分析时看到了 ID003、ID022、ID023、ID032、ID038 的题面，这 5 题在 r2 之后的 dev 成绩中视为已见。
