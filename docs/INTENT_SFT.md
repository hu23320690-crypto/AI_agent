# 意图解析：用可验证合成数据做 SFT

> 一句话：把"qwen3:4b + 1859 token 长提示词"的结构化意图抽取，换成"小模型 + 55 token 短提示词 + LoRA 微调"。训练数据全部由程序合成，每条标签都经过线上同一套校验管线复核。在从未打开过的 test 上，与原方案对比准确率、危险错误和延迟。

[预注册计划](plans/INTENT_SFT_PLAN.md) · [开发日志](INTENT_SFT_DEV_LOG.md) · 代码 [`training/intent_sft/`](../training/intent_sft/)

## 1. 任务

用户的报告请求（如"2025 年三月只列滤网还剩几天和覆盖比例，顺便问下 HEPA 能水洗吗？"）要被解析成 `IntentProposal` JSON，包括字段映射与未知字段、范围、目标月与锚点、比较基准、排除项、知识子问。之后由 V1–V10 校验与规则合并。评分按冻结的九槽合同，**全部槽位都正确才算对**，并把错误分为危险 / 范围错误 / 安全失败 / 其他四级。

难点在于：同义改写与限定词（"墙角覆盖率"不是"覆盖率"）、相对月份的锚点（上一轮目标 / 本轮查询月 / 今天 / 未知事件）、比较中目标与基准的角色、否定与更正、多轮指代。

## 2. 方法

### 2.1 结构先行的合成数据

```
采样结构化意图 ──► 模板渲染成中文原话 ──► 标签 = 结构本身（不来自任何模型）
        │                                   │
        └──── 真实 resolve 管线（hybrid + llm_only）复核：九槽必须与金标准一致，
              原文锚定检查：每个 mention / 月份 / 知识子问都必须逐字出现在原文里
```

- 9 个题型，对应 SCORING 合同的各类现象；8000 条，构造阶段跳过率约 4%。
- 25% 使用**虚构目录**（"星辉率""晶片寿命"等）和 2030 年代的月份，迫使模型读取输入里的 `field_catalog`，而不是背下 37 个演示字段。
- 字段改写词表：gemma4:12b 为每个字段提出 12 个候选，**人工逐条筛选**。凡是可能指向另一字段的（例如泛泛的"滤网"说法）、带限定词的、与 dev 雷同的，一律删除。
- 训练样本的模型输入由线上同一个函数 `build_messages()` 生成，并在 resolve 实际调用时捕获参数，保证训练和线上**逐字节同构**。

### 2.2 训练与部署

- Qwen3-0.6B / 1.7B / 4B，LLaMA-Factory LoRA（r16，all-linear，1 epoch，有效 batch 16）；4B 用 4bit QLoRA。
- 短提示词（4 行，不含规则和示例）。规则由数据"学进权重"，系统提示词从 1859 token 降到 55 token。
- 合并 → GGUF q8_0 → Ollama，接入方式是 `config/intent.yml` 中的 `model_name` / `prompt` / `schema_constrained` 三个开关，默认值保持原行为。

## 3. 结果

> 在封存 test 上，SFT 1.7B 的 hybrid 完全正确率为 **93%**，同日 qwen3:4b 长提示词基线为 83%；危险错误 **9 → 3**，解析 p95 **1.21 s → 0.81 s**。0.6B 为 90%，p95 0.46 s，**是唯一同时满足 S1–S3 的配置**。

### 3.1 test 主结果

test 共 100 题。每个配置在 llm_only 和 hybrid 两种模式下各重复 3 次，2026-10-31 同机、同代码一次跑完，共 10 组，都是登记批次。

| 配置 | 解码 | llm_only 完全正确 | hybrid 完全正确 | 最大危险错误 llm_only / hybrid | hybrid p50 / p95（s） |
| --- | --- | ---: | ---: | ---: | --- |
| qwen3:4b + 长提示词（同日基线） | schema | 78.0% | 83.0% | 16 / 9 | 1.040 / 1.210 |
| SFT 0.6B | 无约束 | 89.0% | 90.0% | 10 / 7 | **0.355 / 0.459** |
| SFT 1.7B | 无约束 | **94.0%** | **93.0%** | **5 / 3** | 0.643 / 0.811 |
| SFT 4B（QLoRA） | 无约束 | 93.0% | **93.0%** | **5 / 3** | 1.298 / 1.550 |
| SFT 1.7B（消融） | schema | 75.7%（最差 75.0%） | 78.0% | 14 / 8 | 0.902 / 1.042 |
| *P3 正式成绩（参照）* | *schema* | *79%* | *80%* | *15 / 10* | *—* |

- 除 1.7B + schema 的 llm_only 外，每组 3 次重复的完全正确数都相同（温度为 0）。因此重复只能反映系统层面的非确定性，不能当作抽样误差。
- 10 组都没有执行失败，没有回退，也没有被预算跳过。
- 同日基线的 hybrid 比 P3 正式成绩高 3 个点（83% 对 80%）。无论和哪一个比，结论方向都一样。
- 系统提示词从 1859 token 降到 55 token（Qwen3 分词器计数）。用户侧 JSON 两种方案相同。
- 原始数据：`evaluation/results/intent_sft_final_test_*`。表中数字由 `training/intent_sft/report.py` 从各组的 `summary.json` 汇总，未读取逐题结果。

### 3.2 预设判定（[计划第 8 节](plans/INTENT_SFT_PLAN.md#8-预设判定报告时逐项写是否)）

| 判定 | 0.6B | 1.7B | 4B |
| --- | --- | --- | --- |
| S1：hybrid 最差完全正确 ≥ 80% | 是（90%） | 是（93%） | 是（93%） |
| S2：最大危险错误 ≤ 10 | 是（7） | 是（3） | 是（3） |
| S3：p95 ≤ 同日基线的 50%（≤ 0.605 s） | **是**（0.459 s，38%） | **否**（0.811 s，67%） | **否**（1.550 s，128%） |
| S4：规模曲线 | 见 3.3 | | |

计划要求 S1–S3 由**同一个**模型满足，0.6B 做到了。准确率最高的 1.7B 达到了 S1 和 S2，但 p95 只降到基线的 67%，没有达到 S3 的 50% 门槛。

### 3.3 观察

- **规模曲线**：从 0.6B 到 1.7B，准确率 +3 点，危险错误 7 → 3。从 1.7B 到 4B，准确率不再提升，延迟翻倍（4B 导出为 q8_0，见第 6 节）。在这个任务上，1.7B 是准确率与成本的折中点；如果更看重延迟，0.6B 只差 3 个点。
- **规则学进了权重**：hybrid 下，基线每 100 题平均触发 31 次校验冲突（3 次合计 93 次，最多的是 `qualifier_dropped` 21 次、`mention_unanchored_kept` 12 次、`negated_field_selected` 12 次）。三个 SFT 模型每 100 题都只触发 4 次。也就是说，原来靠 V2–V10 事后纠正的规则，SFT 模型在生成时就已经遵守了。
- **校验层仍然有用**：从 llm_only 到 hybrid，SFT 的危险错误仍在下降（1.7B 5 → 3，0.6B 10 → 7）。所以应保留 hybrid，不能只用模型输出。
- **约束解码消融**：1.7B 开启 JSON Schema 约束后，hybrid 从 93% 降到 78%（-15 点），p50 反而从 0.64 s 涨到 0.90 s。`field_not_in_catalog` 冲突从 0 次增加到 81 次（每次运行 27 次），说明约束语法改变了切分，模型输出了目录外的字段名。dev 上是 -10 点，方向一致。
- **dev 与 test 差距不大**：1.7B 在 dev 上 95%、test 上 93%；4B 为 97.5% 和 93%；0.6B 为 87.5% 和 90%。合成数据学到的能力迁移到了由别人编写、本实验从未打开过的 test 上。

> 登记批次第一次启动时，批处理在调用评测之前就挂起了，没有产生任何结果。之后以相同配置重新启动，过程见[计划修订 2](plans/INTENT_SFT_PLAN.md#修订-22026-10-31test-无任何结果产生)。

## 4. 补充实验（[计划修订 3](plans/INTENT_SFT_PLAN.md#修订-32026-10-31第-7-节结果已报告补充实验开始前)）

以下实验在主结论报告后、训练任何补充模型前登记。它们只用来说明各项设计的作用，最终模型和 S1–S4 判定都不变。执行中的两处调整（E3 改用 batch 4 × 累积 4、E6 增加同场基线）见[计划修订 4](plans/INTENT_SFT_PLAN.md#修订-42026-10-31e3-训练两次失败后补充实验尚未产生任何-test-结果)，小结见 4.7。

### 4.1 E1：差距是否超出偶然

对 hybrid 模式的 test 结果逐题配对（每题取 3 次重复的多数结果；所有运行中都没有哪题在重复之间结果不同）。检验方法为精确 McNemar，95% CI 为配对 bootstrap（10000 次），6 组比较做 Holm 校正。

| 对比（B 对 A） | A / B 正确 | 差 | 95% CI | 仅 A 对 / 仅 B 对 | p | Holm p |
| --- | --- | ---: | --- | --- | ---: | ---: |
| SFT 0.6B 对基线 | 83% / 90% | +7 | [−1, +15] | 5 / 12 | 0.144 | 0.430 |
| SFT 1.7B 对基线 | 83% / 93% | +10 | [+2, +18] | 4 / 14 | 0.031 | 0.154 |
| SFT 4B 对基线 | 83% / 93% | +10 | [+2, +18] | 4 / 14 | 0.031 | 0.154 |
| 1.7B 对 0.6B | 90% / 93% | +3 | [−1, +8] | 1 / 4 | 0.375 | 0.750 |
| 1.7B 对 4B | 93% / 93% | 0 | [−3, +3] | 1 / 1 | 1.000 | 1.000 |
| 1.7B 无约束 对 1.7B schema | 78% / 93% | +15 | [+7, +23] | 2 / 17 | 0.0007 | **0.004** |

**结论**：100 题的 test 上，只有"关闭约束解码"的作用在多重比较校正后仍然显著。SFT 1.7B / 4B 相对基线 +10 点，bootstrap 区间不含 0，未校正 p = 0.031，但 Holm 校正后 p = 0.154。因此只能说"方向一致、幅度约 10 点"，不能说"显著优于"。要得出更强的结论，需要更大的独立 test。

E2–E4 的配对检验用同样的方法，但**不属于预注册的比较族**，只作描述。下文分别列出 hybrid 和 llm_only 的结果；llm_only 不经过校验层，更直接反映模型本身的差别。

### 4.2 E2：数据量曲线

从 r2 的 7600 条中按 seed 20261101 抽取嵌套子集，1.7B，其余配方不变（1 epoch，所以步数随数据量减少）。2000 点就是 E4 的程序标签组：教师标注没有失败样本，没有剔除任何样本，两份数据的 SHA256 相同。

| 训练条数 | 优化步数 | llm_only | hybrid | 最大危险错误 llm_only / hybrid |
| ---: | ---: | ---: | ---: | ---: |
| 1000 | 63 | 81% | 87% | 16 / 9 |
| 2000 | 125 | 88% | 91% | 11 / 5 |
| 4000 | 250 | 91% | 92% | 8 / 5 |
| 7600（r2，主表） | 475 | **94%** | **93%** | **5 / 3** |
| *qwen3:4b 基线（参照）* | — | *78%* | *83%* | *16 / 9* |

| 对比（B 对 A） | 模式 | 差 | 95% CI | 仅 A 对 / 仅 B 对 | p |
| --- | --- | ---: | --- | --- | ---: |
| 7600 对 1000 | hybrid | +6 | [+1, +12] | 1 / 7 | 0.070 |
| 7600 对 1000 | llm_only | +13 | [+7, +20] | 0 / 13 | 0.0002 |
| 7600 对 4000 | hybrid | +1 | [−2, +5] | 1 / 2 | 1.000 |
| 7600 对 4000 | llm_only | +3 | [0, +7] | 0 / 3 | 0.250 |

- 1000 条（63 步）的 hybrid 已经达到 87%，高于基线的 83%。hybrid 在 4000 条之后基本持平。
- llm_only 一直在上升（81 → 88 → 91 → 94），危险错误同步下降（16 → 5）。也就是说，增加数据主要是让模型**自己**做对，减少对校验层的依赖。
- 当天的训练每步比前一天的 r2 慢（4.4～5.5 s 对 2.95 s，见[计划修订 4](plans/INTENT_SFT_PLAN.md#修订-42026-10-31e3-训练两次失败后补充实验尚未产生任何-test-结果)），所以表中只列步数，不比较训练时间。

### 4.3 E3：虚构目录有没有用

seed 和条数都与 r2 相同，只把虚构目录比例从 25% 改为 0%。E3 的训练两次在同一步显存不足，改用 batch 4 × 累积 4（有效 batch 不变），见计划修订 4。

| 模型 | llm_only | hybrid | 最大危险错误 llm_only / hybrid |
| --- | ---: | ---: | ---: |
| r2（25% 虚构目录） | **94%** | **93%** | **5 / 3** |
| E3（0% 虚构目录） | 90% | 90% | 9 / 6 |

配对：hybrid +3 点（[0, +7]，仅 r2 对 3 题 / 仅 E3 对 0 题，p = 0.25）；llm_only +4 点（[+1, +8]，4 / 0，p = 0.125）。

**结论**：去掉虚构目录后，test 上低 3～4 个点。不一致的题全部偏向 r2，但题数太少，不显著。E5 的探针进一步说明，这部分差别**不是**因为 E3 模型不会读目录（见 4.5）。

### 4.4 E4：标签来源（程序标签 vs 大模型教师标签）

对 2000 条子集，用线上原方案（qwen3:4b + 长提示词，llm_only，schema 约束解码）重新标注，替换程序标签后训练 1.7B。输入完全相同（由存储的请求重建，并逐字节核对）。

**教师标签本身的质量**（按九槽金标准）：2000 条中通过 62.6%，与程序标签的 JSON 完全一致只有 18.7%；没有失败（无回退、无空提议）。分题型看，`qualifier_distractor` 只有 14.6%，`month_resolution` 39.3%，`negation_correction` 45.2%，最高的 `multi_turn_reference` 为 92.1%。

| 训练标签（2000 条） | llm_only | hybrid | 最大危险错误 llm_only / hybrid | hybrid p50（s） |
| --- | ---: | ---: | ---: | ---: |
| 程序标签 | **88%** | **91%** | **11 / 5** | 0.628 |
| qwen3:4b 教师标签 | 76.3%（最差 76%） | 83.7%（最差 83%） | 17 / 10 | 0.632 |
| *教师本身（qwen3:4b 基线）* | *78%* | *83%* | *16 / 9* | *1.040* |

配对：llm_only +12 点（[+6, +19]，仅教师组对 0 题 / 仅程序组对 12 题，p = 0.0005）；hybrid +7 点（[+2, +13]，1 / 8，p = 0.039）。教师组 hybrid 有 1 题在 3 次重复间结果不同，按多数计。

**结论**：用教师标签训练的学生，准确率和危险错误都**回到了教师自己的水平**（llm_only 76% 对 78%，hybrid 84% 对 83%）。蒸馏把教师的错误一并学了过去。换成可验证的程序标签，同样的输入、同样的步数多出 7～12 个点。也就是说，**准确率的提升来自标签，而不是来自微调本身**；延迟的下降来自小模型加短提示词，两种标签的学生都在 0.63 s 左右。

### 4.5 E5：目录迁移探针

新写一组与训练词表不相交的虚构字段名（如"玄冰均值""碧落余量"），用同一生成器生成 300 条，全部使用这组目录（同样是 2030 年代的月份），并同样经过 resolve 复核。每个模型、每种模式各跑 1 次。

| 模型 | llm_only | hybrid | 危险错误 llm_only / hybrid（共 300 题） | hybrid p50（s） |
| --- | ---: | ---: | ---: | ---: |
| qwen3:4b + 长提示词 | 69.3% | 82.0% | 43 / 18 | 1.106 |
| 1.7B r2 | **99.0%** | **99.3%** | **1 / 0** | 0.674 |
| 1.7B E3（训练中从未见过虚构目录） | 97.7% | 98.7% | 6 / 3 | 0.680 |

- E3 模型训练时只见过 37 个真实字段名，但在全新的目录上 `fields` 槽仍是 100%。所以 SFT 模型确实在读取输入里的目录，而不是背字段名；做到这一点并**不需要**虚构目录。
- E3 的错误集中在 `comparison_roles`（88%～90%，r2 为 93%～95%）和 llm_only 的 `month_resolution`（95%）。它没见过 2030 年代的月份，这是虚构目录在探针上唯一体现出来的作用。
- **适用范围**：探针与训练数据出自同一套模板。对 SFT 模型来说，只有字段名和年份是新的；虚构字段没有改写说法，题面中的字段名都是原样出现的。对 qwen3:4b 来说，整套模板写法都是新的（`qualifier_distractor` llm_only 只有 17%）。因此探针只隔离"是否读取目录"，qwen3:4b 与 SFT 的差距不能拿来和 test 比较。

### 4.6 E6：同量化（Q4_K_M）下的延迟

主表的 SFT 模型导出为 q8_0，而 qwen3:4b 是 Q4_K_M。E6 用 llama.cpp 官方 `llama-quantize`（b12017）把同一批 r2 adapter 合并后量化为 Q4_K_M，并在同一时段重跑基线（计划修订 4）。

| 配置 | 量化 | llm_only | hybrid | 最大危险错误 llm_only / hybrid | hybrid p50 / p95（s） | p95 / 同场基线 |
| --- | --- | ---: | ---: | ---: | --- | ---: |
| qwen3:4b 长提示词（同场基线） | Q4_K_M | 78% | 83% | 16 / 9 | 1.059 / 1.234 | 100% |
| *qwen3:4b（主表）* | *Q4_K_M* | *78%* | *83%* | *16 / 9* | *1.040 / 1.210* | — |
| SFT 0.6B | Q4_K_M | 88% | 90% | 10 / 6 | **0.305 / 0.355** | **29%** |
| SFT 1.7B | Q4_K_M | 90% | **93%** | 8 / **3** | 0.459 / 0.608 | 49% |
| SFT 4B（QLoRA） | Q4_K_M | **93%** | **93%** | **5** / 4 | 0.881 / 1.080 | 88% |
| *SFT 0.6B / 1.7B / 4B（主表）* | *q8_0* | *89% / 94% / 93%* | *90% / 93% / 93%* | — | *p95 0.459 / 0.811 / 1.550* | — |

- 同场基线与主表的准确率完全相同，p95 只差 2%，说明两个时段的结果可以并列。
- 量化到 Q4_K_M 后，hybrid 准确率三个尺寸都不变，p95 下降 23%～30%。1.7B 和 4B 各有 1 题在每次重复中都输出了结构非法的 JSON（`structure_invalid`），被安全回退到规则，计入分母；1.7B 的 llm_only 因此从 94% 降到 90%。
- **4B 的公平对比**：同为 4B、同为 Q4_K_M 时，SFT 的 p95 是基线的 88%。这 12% 主要来自更短的系统提示词（55 对 1859 token，预填充更少），也可能部分来自输出长度不同（未单独测量）。主表中"4B 比基线慢"是 q8_0 导出造成的。
- 1.7B Q4_K_M 的 p95 为同场基线的 49%，刚好落在 S3 的 50% 门槛内。这是补充实验的描述性结果，**不改变** 3.2 节的判定（预注册的最终模型是 q8_0 导出）。

### 4.7 补充实验小结

1. **标签是关键**：同样的输入，用大模型教师标签训练只能回到教师水平；程序生成、经管线复核的标签多 7～12 个点（E4）。
2. **数据量**：1000 条就超过基线；继续增加数据主要提升模型自己（llm_only）的正确率并减少危险错误（E2）。
3. **虚构目录**：test 上约 +3 点，不显著；读取目录的能力不依赖它（E3、E5）。
4. **延迟**：量化对齐后，SFT 在每个尺寸上都比基线快；4B 对 4B 快 12%，1.7B 快一半（E6）。
5. **显著性**：在 100 题 test 上，主结论"SFT 比基线高约 10 点"未通过 Holm 校正（E1）；E2–E4 的检验不在预注册比较族内，只作描述。

## 5. 排查出的三个坑

| 现象 | 根因 | 处理 |
| --- | --- | --- |
| dev 上目标月与基准月被调换 | 生成器伪相关：比较类样本的 `current_lookup_month` 总等于目标月 | 两个查询月随机排序；其他题型也有 20% 额外查询了别的月份 |
| 换了一版数据，同尺寸模型延迟反而 +70% | Ollama 官方 Qwen3 模板给助手回合插入空思考块，训练格式里没有；`think:false` 还会再改写提示（+4 token） | 写与训练格式逐字一致的模板，专用模型不发送 `think`；用分词器计数核对（143 = 143） |
| 开着 JSON Schema 约束解码时，微调模型准确率下降约 10 个点 | 约束语法会改变分词切分，模型被迫偏离训练时的 token 序列 | 微调模型关闭约束；V1 严格解析与规则回退不变；test 中保留"开约束"一组作消融对照 |

## 6. 局限

- 单一领域、单份演示 CSV；test 只有 100 题，每个配置只有一个批次（3 次重复）。
- 生成器作者读过 dev 的题型和部分题面；dev 用于选择解码方式，dev 数字偏乐观。test 由先前的助手团队编写，本实验期间从未打开。
- 主表的延迟对比不同量化：SFT 导出为 q8_0，qwen3:4b 官方为 Q4_K_M。同量化的对比见 4.6。
- **基座版本不同**：Ollama 的 qwen3:4b 是较新的 Qwen3-2507（上下文 262144），SFT 用的是最初发布的 Qwen3（Hugging Face 的 Qwen3-0.6B / 1.7B / 4B，上下文 40960）。因此这里比较的是"线上提示词方案"和"微调方案"两套系统，不是同一基座上的提示词与微调。
- 生成器在修复前不能跨进程逐字节复现（见[开发日志](INTENT_SFT_DEV_LOG.md#补充实验中发现的问题2026-10-31test-主结论之后)），r1 / r2 以存档的 `train.json` 及其 SHA256 为准。
- 合成数据的语义正确性依赖模板构造；resolve 复核能抓出与原文、校验规则不一致的标签，但抓不出"标签和金标准一起错"。
