# 第三步：RAG 来源治理与工具执行权限

本阶段在既有 Runtime 上增加可验证的来源和执行边界。对应入口是 `rag/security.py`、`rag/vector_store.py`、`rag/rag_service.py` 与 `agent/tools/policy.py`；实际结果见 `RUNTIME_STAGE3_VERIFICATION.md`。

## 威胁模型

攻击者可以提供、修改待入库的 TXT/PDF 文档。程序、配置、来源审批清单和应用维护的索引由管理员控制，攻击者不能修改它们。本机管理员、操作系统被攻破、任意向量数据库写权限不在这个模型内。

审批、摘要和规则检测均不能证明资料中的事实真实。现有 6 份资料只标记为 `demo_allowed`，没有厂商适用性或真实性背书。事实投毒和复杂提示注入仍需第四步专门评测。

## 来源与索引

`config/knowledge_sources.json` 保存每份文件的稳定来源 ID、相对路径、版本、SHA256、状态和审核依据。`config/security.yml` 保存文件/文本/页面上限、风险规则、去重和单来源配额。

- `approved` / `demo_allowed`：仅允许审核过的当前文件摘要和版本。
- `quarantined` / `revoked`：不参与检索。未知、变化或删除的文件也立即不再满足授权，不需要重启。
- 清单缺失、损坏、重复 ID/路径、绝对或越界路径默认拒绝；不跟随来源路径的符号链接和 junction。
- TXT/PDF 都解析已经核对过的同一份字节快照。运行时先比对 SHA256，未授权的变化字节不会进入 PDF 解析。
- 分块保存来源 ID/版本/摘要、片段 ID/摘要、分块配置指纹。缺少这些字段的旧片段不再被信任。

新集合为 `agent_chunks_qwen3_governed_v1`，保留历史集合。`sync` 将无效或撤销分块删除；即使尚未执行物理清理，检索也先按授权片段筛选，再查询向量，BM25 只使用同一批允许片段。

每次检索重新核对来源文件，词法缓存随来源状态、内容或索引分块变化重建。RRF 最终选择最多 3 块来自同一个文件，并去除文本完全重复或相似度不低于 0.96 的候选。允许返回不足 Top5，不用被拒绝的片段补位。单文件配额不等于不同文件来自独立权威来源。

## 管理流程

这些操作只在本地管理员 CLI 中提供，不在 Agent 的工具列表中。

```powershell
# 查看新文件/变化和风险；只隔离，不自动批准
.\.venv\Scripts\python.exe -B scripts/manage.py knowledge scan
# 只读查看当前授权及拒绝原因
.\.venv\Scripts\python.exe -B scripts/manage.py knowledge status
# 人工核对文件与 scan 输出的 SHA256 后审批；替换示例参数
.\.venv\Scripts\python.exe -B scripts/manage.py knowledge approve "新增指南.txt" --sha256 "核对过的64位SHA256" --reason "审核依据"
# 同步已允许版本，并清理无效分块
.\.venv\Scripts\python.exe -B scripts/manage.py knowledge sync
# 使用 status 输出的来源 ID 撤销；替换示例参数
.\.venv\Scripts\python.exe -B scripts/manage.py knowledge revoke "来源ID" --reason "撤销依据"
```

规则包括伪造角色/系统指令、覆盖规则、跨用户取数/泄露指令和隐藏控制字符。这些是保守风险信号：合法安全培训文本引用攻击话术也可能命中。确实需要保留这种文本时，管理员核对内容后可在 `approve` 增加 `--allow-risk`，必须留下审核理由。该选项不是防护成功证明。变化文档需要重新审批；扫描不会重新放行撤销来源。

审批更新使用跨进程锁文件和原子替换，避免部分 JSON 或并发审核丢失。管理员进程异常退出可能留下 `.lock` 文件；确认没有审核进程在运行后再人工处理，程序不擅自删除其他进程的锁。

## 资料隔离与撤销传播

RAG 系统约束与用户问题/检索文本分成不同消息。片段作为保留来源的低信任 JSON 传入；子模型没有工具绑定。每次 RAG 模型请求（含重试）前、生成后、最终提交前均复核来源。

成功对话保留来源校验，后续模型请求继续复核历史依据。如果下一轮开始时发现历史来源已失效，整体清空传给模型的会话历史，再处理新问题；当前轮中途变化则拒绝提交。本阶段采用整体清空，尚未做按消息裁剪。已经展示给用户的旧答案不会被收回。

历史检查和最终提交检查也进入有界等待；文件 I/O 不持有取消/截止时间使用的状态锁。慢校验、超时和取消不能让迟到答案提交。仍不能保证撤销瞬间停止已经开始的远端模型推理，校验和提交之间也没有跨文件系统/数据库的原子事务。

## 工具权限

执行前使用 7 工具白名单和 Pydantic 严格公开参数 schema，拒绝未知工具、多余字段、错误类型，以及模型注入 `runtime/context/state/store/config` 等内部参数。

公开字符串上限：知识 query 3000 字符，city 100，user_id 64，month 20；还遵守整轮工具参数长度预算。查询用户必须来自程序侧当前会话，月份统一规范化。报告上下文必须来自本轮合法查询成功的记录。权限拒绝先于工具执行和工具调用预算占用。

权限拒绝标记在整轮保持，之后合法查询不会覆盖拒绝结论。模型和日志只接收固定安全文字、原因代码，不保留被拒绝的原始参数或普通异常细节。系统约束明确工具结果同样是低信任资料。演示用户选择仍不是登录认证或生产多租户 ACL。

## 验证及边界

离线验证使用临时文件/清单、真实 Chroma、真实 LangChain 图、脚本化模型和本地嵌入；攻击样本不写入真实知识目录。覆盖热缓存后的修改/删除/撤销、旧片段排除、版本替换、误拦截人工复核、单来源挤占、模型重试与提交期间撤销、历史撤销、权限拒绝，以及校验阻塞后的取消/超时。

PDF 管理扫描仍在本进程使用 pypdf。8MB、500 页、50 万字符是输入/结果上限，不能替代独立进程沙箱和硬内存限制。整个目录/索引在本地小规模下核对，尚未进行大型语料或高并发压测。第四步将报告真实模型攻击成功率、误拦截率和正常对照，当前不能宣称消除 RAG 投毒。
