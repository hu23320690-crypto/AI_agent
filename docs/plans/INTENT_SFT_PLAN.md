# 意图解析 SFT 实验计划（预注册）

日期：2026-10-30（Australia/Sydney）。分支 `feat/intent-sft`。本文件在生成任何训练数据、训练任何模型之前写定；之后的改动只追加修订记录，不改写原文。

## 1. 问题与动机

`agent/intent` 目前用 qwen3:4b 加约 2.6k 字的长提示词做结构化抽取（`IntentProposal` JSON），再经 V1–V10 校验合并。P3 正式 test（100 题）成绩：

| 模式 | 完全正确（均值/最差） | 最大危险错误 |
| --- | --- | --- |
| rule | 16% / 16% | 13 |
| llm_only（qwen3:4b + 提示词） | 79% / 79% | 15 |
| hybrid（qwen3:4b + 提示词 + 校验） | 80% / 80% | 10 |

提示词方案有三个问题：长提示词带来固定的预填充延迟（P3 解析 p50≈1.2s）；规则越写越长，靠追加自然语言约束修错的收益递减（P3.1 只多对 1 题）；4B 模型是能否运行的下限，无法换更小的模型。

本实验研究：**用可验证的合成数据做监督微调（SFT），能否让更小的模型、配更短的提示词，达到或超过提示词方案的准确率和安全性，同时降低延迟。**

## 2. 不变的部分

- 输出仍是 `agent/intent/schema.py` 的 `IntentProposal`；V1 JSON 校验、V2–V10 语义校验、resolve 合并逻辑全部不改。微调模型只是替换"提议者"。
- 评分合同、金标准、`evaluation/intent_eval.py` 的评分代码不改。
- 推理侧保持 P3 的设置：temperature=0、reasoning=False、Ollama JSON Schema 约束解码、num_predict≤384。
- 默认模式保持 `rule`；本实验不切换默认值。

## 3. 数据隔离

- **只**允许读取 `evaluation/intent_v1_r1/dev.jsonl`（40 题），以及 SCORING 合同、提示词、校验代码。
- 不打开 `test.jsonl`、`cases.jsonl`、`TEST_GOLD_REVIEW.md`、各 Agent 测试题面，也不打开任何 test 运行的逐题原始结果。test 只用于第 7 节的最终一次评测。
- 训练数据全部由生成器合成，不复制、不改写 dev 题面。dev 只用来选模型和调整生成器，所以 dev 成绩是乐观估计，不作为结论。
- 已知局限：生成器作者（本助手）读过 dev 的题型与说明，题型分布会向 dev 靠拢。test 由先前的助手团队编写，本实验期间从未打开，是唯一的"未见"证据。

## 4. 训练数据：结构先行、管线验证

1. 先采样**结构化意图**：会话目录、today、查询月、上一轮意图、历史原话、字段（含改写、限定词、未知指标）、范围、目标月与锚点、比较基准、排除项、知识子问。再按模板把它渲染成用户原话。标签由结构直接得出，不来自任何模型输出。
2. 每条样本把标签（`IntentProposal`）交给真实的 `resolve_turn_intent`（hybrid 和 llm_only 两种模式）。经 `adapt_result` 适配后，必须与生成器给出的九槽金标准**完全一致**，且 hybrid 下不得触发任何校验冲突。不一致的样本说明生成器有误，直接丢弃，并统计丢弃率。
3. 目录分两类：真实 CSV 目录（领域适配），以及一部分虚构目录（迫使模型读 `field_catalog`，而不是记住 37 个字段名）。
4. 模型输入与线上**逐字节同构**：训练样本由 `llm_parser` 中的同一函数构造 HumanMessage JSON。

## 5. 模型与训练

- 基座：Qwen3-0.6B、Qwen3-1.7B、Qwen3-4B（Hugging Face 原始权重）。
- 方法：LLaMA-Factory LoRA（rank 16，all-linear）；单卡显存放不下时，4B 改用 4bit QLoRA，并在报告中注明。
- 提示词：微调模型使用短提示词 `prompts/intent_parser_sft.txt`（只说明任务与输入字段，不含规则和示例），以检验规则能否由数据"学进权重"。
- 部署：合并 LoRA → GGUF q8_0 → Ollama，和基线走同一条 ChatOllama 路径。

## 6. 开发轮次（只用 dev）

最多 3 轮。每轮可以改生成器、数据量和超参，每轮都记录版本、数据 SHA256 和 dev 全部结果。之后冻结最终配置，不再修改。

## 7. 最终评测（test，各一次登记批次）

- 每个最终模型在 test 上跑 llm_only 与 hybrid 两种模式，各重复 3 次，报告均值和最差值，不挑选重跑。
- 同日、同机、同代码重跑一次 qwen3:4b 提示词基线（llm_only 与 hybrid，各 3 次），用于延迟对照。准确率另与 P3 正式成绩并列，两者都报。
- 指标：完全正确率、分槽准确率、危险错误 / wrong_scope / safe_fail 分级、执行失败数、解析延迟 p50/p95（nearest-rank）、输入 token 数。

## 8. 预设判定（报告时逐项写"是/否"）

- S1：存在一个 SFT 模型，hybrid 模式下 test 最差完全正确率 ≥ 80%（P3 hybrid）。
- S2：该模型最大危险错误 ≤ 10（P3 hybrid）。
- S3：该模型解析延迟 p95 ≤ 同日基线 p95 的 50%。
- S4（规模曲线）：报告 0.6B / 1.7B / 4B 三点的准确率与延迟，不论单调与否。

未达标照样报告；不因 test 结果回改数据、提示词或模型。

## 9. 不能声称的内容

单一领域、单份演示 CSV；test 只有 100 题，且每个配置只跑一次批次；温度为 0 时的重复主要反映系统层面的非确定性。不能据此作出显著性、跨领域或生产可靠性结论。
