# 意图解析 SFT 实验计划（预注册）

日期：2026-10-30（Australia/Sydney）。分支 `feat/intent-sft`。本文件在生成任何训练数据、训练任何模型之前写定；之后的改动只追加修订记录，不改写原文。

## 1. 问题与动机

`agent/intent` 目前用 qwen3:4b 加约 2.6k 字的长提示词做结构化抽取（`IntentProposal` JSON），再经 V1–V10 校验合并。P3 正式 test（100 题）成绩：

| 模式 | 完全正确（均值/最差） | 最大危险错误 |
| --- | --- | --- |
| rule | 16% / 16% | 13 |
| llm_only（qwen3:4b + 提示词） | 79% / 79% | 15 |
| hybrid（qwen3:4b + 提示词 + 校验） | 80% / 80% | 10 |

提示词方案有三个问题：长提示词带来固定的预填充延迟（P3 解析 p50≈1.2s）；规则越写越长，靠追加自然语言约束修错的收益递减（P3.1 只多对 1 题）；4B 模型是能否运行的下限，无法换更小的模型。

本实验研究：**用可验证的合成数据做监督微调（SFT），能否让更小的模型、配更短的提示词，达到或超过提示词方案的准确率和安全性，同时降低延迟。**

## 2. 不变的部分

- 输出仍是 `agent/intent/schema.py` 的 `IntentProposal`；V1 JSON 校验、V2–V10 语义校验、resolve 合并逻辑全部不改。微调模型只是替换"提议者"。
- 评分合同、金标准、`evaluation/intent_eval.py` 的评分代码不改。
- 推理侧保持 P3 的设置：temperature=0、reasoning=False、Ollama JSON Schema 约束解码、num_predict≤384。
- 默认模式保持 `rule`；本实验不切换默认值。

## 3. 数据隔离

- **只**允许读取 `evaluation/intent_v1_r1/dev.jsonl`（40 题），以及 SCORING 合同、提示词、校验代码。
- 不打开 `test.jsonl`、`cases.jsonl`、`TEST_GOLD_REVIEW.md`、各 Agent 测试题面，也不打开任何 test 运行的逐题原始结果。test 只用于第 7 节的最终一次评测。
- 训练数据全部由生成器合成，不复制、不改写 dev 题面。dev 只用来选模型和调整生成器，所以 dev 成绩是乐观估计，不作为结论。
- 已知局限：生成器作者（本助手）读过 dev 的题型与说明，题型分布会向 dev 靠拢。test 由先前的助手团队编写，本实验期间从未打开，是唯一的"未见"证据。

## 4. 训练数据：结构先行、管线验证

1. 先采样**结构化意图**：会话目录、today、查询月、上一轮意图、历史原话、字段（含改写、限定词、未知指标）、范围、目标月与锚点、比较基准、排除项、知识子问。再按模板把它渲染成用户原话。标签由结构直接得出，不来自任何模型输出。
2. 每条样本把标签（`IntentProposal`）交给真实的 `resolve_turn_intent`（hybrid 和 llm_only 两种模式）。经 `adapt_result` 适配后，必须与生成器给出的九槽金标准**完全一致**，且 hybrid 下不得触发任何校验冲突。不一致的样本说明生成器有误，直接丢弃，并统计丢弃率。
3. 目录分两类：真实 CSV 目录（领域适配），以及一部分虚构目录（迫使模型读 `field_catalog`，而不是记住 37 个字段名）。
4. 模型输入与线上**逐字节同构**：训练样本由 `llm_parser` 中的同一函数构造 HumanMessage JSON。

## 5. 模型与训练

- 基座：Qwen3-0.6B、Qwen3-1.7B、Qwen3-4B（Hugging Face 原始权重）。
- 方法：LLaMA-Factory LoRA（rank 16，all-linear）；单卡显存放不下时，4B 改用 4bit QLoRA，并在报告中注明。
- 提示词：微调模型使用短提示词 `prompts/intent_parser_sft.txt`（只说明任务与输入字段，不含规则和示例），以检验规则能否由数据"学进权重"。
- 部署：合并 LoRA → GGUF q8_0 → Ollama，和基线走同一条 ChatOllama 路径。

## 6. 开发轮次（只用 dev）

最多 3 轮。每轮可以改生成器、数据量和超参，每轮都记录版本、数据 SHA256 和 dev 全部结果。之后冻结最终配置，不再修改。

## 7. 最终评测（test，各一次登记批次）

- 每个最终模型在 test 上跑 llm_only 与 hybrid 两种模式，各重复 3 次，报告均值和最差值，不挑选重跑。
- 同日、同机、同代码重跑一次 qwen3:4b 提示词基线（llm_only 与 hybrid，各 3 次），用于延迟对照。准确率另与 P3 正式成绩并列，两者都报。
- 指标：完全正确率、分槽准确率、危险错误 / wrong_scope / safe_fail 分级、执行失败数、解析延迟 p50/p95（nearest-rank）、输入 token 数。

## 8. 预设判定（报告时逐项写"是/否"）

- S1：存在一个 SFT 模型，hybrid 模式下 test 最差完全正确率 ≥ 80%（P3 hybrid）。
- S2：该模型最大危险错误 ≤ 10（P3 hybrid）。
- S3：该模型解析延迟 p95 ≤ 同日基线 p95 的 50%。
- S4（规模曲线）：报告 0.6B / 1.7B / 4B 三点的准确率与延迟，不论单调与否。

未达标照样报告；不因 test 结果回改数据、提示词或模型。

## 9. 不能声称的内容

单一领域、单份演示 CSV；test 只有 100 题，且每个配置只跑一次批次；温度为 0 时的重复主要反映系统层面的非确定性。不能据此作出显著性、跨领域或生产可靠性结论。

## 修订记录（只追加）

### 修订 1（2026-10-30，test 未打开）

开发中发现并修正了服务路径问题，详见 [开发日志](../INTENT_SFT_DEV_LOG.md#服务路径修正不算调参轮次)。第 2 节"推理侧保持 P3 的设置"对 SFT 模型做以下调整，qwen3:4b 基线不变：

- **Ollama 模板**：SFT 模型使用与训练格式逐字一致的模板，并且不发送 `think` 参数。原因是官方 Qwen3 模板和 `think:false` 都会改写提示，造成训练与推理不一致。
- **JSON Schema 约束解码**：SFT 模型关闭（`AGENT_INTENT_SCHEMA=0`），V1 仍严格解析；qwen3:4b 基线保持开启。为体现这一选择的影响，第 7 节的最终评测**另外**跑一组"1.7B + schema 约束"的 test，作为消融对照。
- **训练方式**：4B 因显存限制使用 4bit QLoRA，与第 5 节允许的情形一致。
- 开发只用了 2 轮（第 6 节上限为 3 轮），配置已在第 2 轮后冻结。

### 修订 3（2026-10-31，第 7 节结果已报告，补充实验开始前）

**目的**：回答两个问题：各项设计是否真的有用；主表中的差距是否超出偶然。**最终模型和 S1–S4 判定不因补充实验改变**。以下实验在训练任何补充模型之前写定，结果不论好坏都报告。

- **E1 配对显著性**：对第 7 节已完成的 test 运行逐题配对，每题取 3 次重复的多数结果，做精确 McNemar 检验和配对 bootstrap 95% CI（10000 次，seed 20261031），用 Holm 校正多重比较。比较族共 6 组，全部为 hybrid 模式：SFT 0.6B、1.7B、4B 分别对同日基线；1.7B 对 0.6B；1.7B 对 4B；1.7B 无约束对 1.7B schema。脚本只输出汇总统计，不显示逐题内容。
- **E2 数据量曲线**：从 r2 的 train（7600 条）中按 seed 20261101 抽取嵌套子集，大小为 1000、2000、4000。训练配方不变（1 epoch），所以步数会随数据量减少。模型为 1.7B。
- **E3 虚构目录消融**：seed 和条数与 r2 相同，只把虚构目录比例从 25% 改为 0%，训练 1.7B。
- **E4 标签来源消融**：对 E2 的 2000 条子集，用 qwen3:4b + 长提示词（llm_only 原始提议）重新标注，训练 1.7B。对照组为同一批输入、使用程序标签的 1.7B。同时报告教师标签按九槽金标准的通过率。教师失败（回退或无提议）的样本在两组中同时剔除，因此 E2 的 2000 点使用剔除后的同一批样本。
- **E5 目录迁移探针**：新写一组与训练词表不相交的虚构字段名，用同一生成器生成 300 条样本（seed 20261101），全部使用这组目录，并同样经过 resolve 复核。评测 qwen3:4b 基线、1.7B r2 和 E3 模型，llm_only 与 hybrid 各 1 次。这个探针属于合成分布，只隔离"模型是否读取目录"，不代表真实的新领域。
- **E6 同量化延迟**（仅在获准下载 llama.cpp 官方量化工具后进行）：把 SFT 模型量化为 Q4_K_M，与 Q4_K_M 的 qwen3:4b 基线比较。test 上 llm_only 与 hybrid 各跑 3 次。
- **评测设置**：E2–E4 的模型在 test 上跑 llm_only 与 hybrid，各 3 次，设置与主表相同（短提示词、无约束解码、训练一致模板）。
- **关于再次使用 test**：test 已用于主结论。补充实验再次使用 test，只用来描述各项设计的作用，不用于选择或修改最终模型。
- **取消原定的"去掉管线复核"消融**：r1、r2 最终数据中复核的拒绝数都是 0（被跳过的只是构造失败和重复样本），去掉复核得到的数据与原数据完全相同。复核的作用是在开发期充当生成器的测试，标签质量的影响改由 E4 检验。

### 修订 4（2026-10-31，E3 训练两次失败后；补充实验尚未产生任何 test 结果）

- **E3 训练失败**：1.7B 的 E3 训练两次都在第 135/475 步失败（先是 cuBLAS 内部错误，随后 CUDA out of memory），没有产生模型。两次停在同一步。E3 数据的长度分布与 r2 相同（Qwen3 分词器计数：均值 248、最长 346 token），所以不是样本过长。当天的 1.7B 训练每步 4.4～5.5 s，前一天 r2 为 2.95 s（同为 batch 8 × 累积 2、交流供电），说明当天可用显存比训练 r2 时少，部分已溢出到共享内存。失败日志保存为 `runs/1.7B-nofict/train_oom.log`。
- **处理**：E3 改为每卡 batch 4 × 梯度累积 4（与 4B 相同），有效 batch 仍为 16，其余设置不变。transformers 5.6 按整个累积步的 token 数归一化损失，打乱顺序与 batch 大小无关，所以每个优化步用到的 16 条样本与 8 × 2 相同，差别只在数值舍入和 dropout 随机数。E2、E4 已按 8 × 2 训练完成，不重训。
- **E6 增加同场基线**：GPU 状态已与主表那批不同，跨时段比较延迟不可靠。因此在 E6 的同一时段，按主表设置重跑 qwen3:4b 长提示词基线（test，两种模式各 3 次），E6 的延迟以同场基线为准，主表基线的数字一并列出。
