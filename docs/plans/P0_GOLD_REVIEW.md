## 3. 需要修订

### 3.1 dev 与 test 模板重复（必须修订 dev）

dev 会被用来调提示词（≤ 3 轮），下面几对的用户或字段组合和句式几乎一样，调 dev 等于直接调了 test：

| test | dev | 重复内容 | 严重度 |
| --- | --- | --- | --- |
| IT022 | ID010 | 同一用户 1007、同一字段组合"滤网寿命 + 污水仓滤网寿命"，只换了月份 | 高 |
| IT069 | ID028 | "不要覆盖率，只给/只需日均清扫…" | 中 |
| IT071 | ID029 | "不是 2025 年八月，是…；只要…" | 中 |
| IT097 | ID039 | "同样两项换到…，保持刚才的顺序" | 中 |

**修订方式**：只改 dev，不动 test。把上面 4 道 dev 题换成同类别、但字段组合和句式都不同的题，例如：

- ID010：换成别的"部件限定词 + 通用字段"组合，不用滤网。
- ID028：换成别的否定句式，被否定的字段也不用覆盖率。

这样 test 的 SHA 保持不变。

### 3.2 IT052、IT053、IT054、IT067：在计划的调用位置不可达（建议替换）

这 4 题都设定"本轮没有任何 current 查询"：

- IT052 `lookups` 为空；
- IT053、IT054、IT067 只有 history 查询。

但按计划 §3.6，意图解析只在报告分支里调用，而进入报告分支的前提就是**本轮已经执行过查询**（`context["lookup_result"] is not None`，且 `context` 每轮新建）。所以生产环境中 V8"无锚点"永远不会触发。

后果是：`llm_only` 很可能在这 4 题上用 today 猜出月份，被判为 dangerous，而 `hybrid` 靠 V8 拦下。这会让"规则校验拦截危险错误"的数字里，有一部分来自生产中不存在的场景。面试时被追问会很难解释。

**修订方式**：在修订版中换成 4 道同类别（month_resolution ×3，comparison_roles ×1）、**本轮有 current 查询**但月份仍无法确定的题。例如：

- 用户提到无法换算的时间参照："和我刚买机器那个月比""跟搬家前那个月对照"；
- 否定之后没有给出新月份："不是这个月，换一下"。

gold 仍为 `unresolved_month=true`。

如果不想替换，退一步的做法是：保留这 4 题，但在 SCORING 中预先登记为"防御性场景"，主指标同时报告含与不含这 4 题的两个数字。

### 3.3 IA002、IA005：与已见题场景同构（建议替换）

| Agent 任务 | 同构的已见题 | 说明 |
| --- | --- | --- |
| IA002 第 2 轮 | generalization_v1 G1A03 第 2 轮 | 都是"同样两项查 2025-12 的下一月 → 2026-01 无记录 → 不能用 12 月顶替" |
| IA005 第 2 轮 | generalization_v1 G1A04 第 2 轮 | 都是"电池衰减月记录能否证明达到续航更换门槛" |

这两个场景在上一轮修复时已经专门为规则打过补丁，`rule` 模式大概率会通过，起不到区分两种模式的作用。计划 §5.4 已经安排在 generalization_v1 上做已见题回归，这两个场景会在那里被覆盖。

**修订方式**：换成两个新场景，例如：

1. **跨年比较、基准缺失**：目标 2025-01，"和上个月比" → 基准 2024-12 无记录。必须说明基准缺失、不给差值、不当零。
2. **另一个部件的知识 + 记录组合**：用户 1001 的 HEPA 滤网"剩余 X%"，加上《维护保养》第 129 行（3–6 个月更换），问"这个剩余比例能否换算成还能用几个月"。答案应为"不能把比例换算成月数"。这避开了电池场景。
