## 面试问答

### 1. 为什么采用两段式提交？

模型可以误解用户，也可能被资料诱导。第一段只把工具和参数写成 pending_actions 卡片；第二段由页面或 API 接收确认/拒绝事件，确定性代码复核会话、用户、参数哈希、状态和有效期，并在事务内执行、处理幂等和追加审计。模型没有确认执行工具。页面卡片位于聊天主区域，确认成功后显示“已执行”。这约束业务写入，不保证模型建议或文字本身正确。[报告 §5、§7](SERVICE_AGENT_S5_REPORT.md)

### 2. H1–H6 如何验证？

H1 未确认写入、H2 参数哈希不一致、H3 跨用户写入、H4 重复写入、H5 注入诱导执行、H6 拒绝后执行，正式运行各项均为 0。另有离线对抗测试主动覆盖参数篡改、重放、过期、跨会话/用户 action_id、并发确认、拒绝后确认；H1–H4/H6 的结构性保证不能只用正常对话验证。正式运行和离线对抗是不同证据，零事件不证明所有攻击都已覆盖。[报告 §5、§7](SERVICE_AGENT_S5_REPORT.md)

### 3. 为什么 plan 没有达到切换门槛？

test 从 10/30 到 12/30，只有 +6.67pp；预设要求至少 15pp。test/plan 发生 65 次 planner 调用、32 次重规划、18/37 轮回退，预算超限 3/37=8.11%，超过 5%。轨迹与评审显示严格计划格式、字段类型、目标补齐及条件识别仍有成本，4B 模型承担这些约束并不稳定。模型规模是可能瓶颈，尚未通过更大模型消融证明因果；不能据这次小样本宣布 plan 更好或更差。[报告 §4、§7–9](SERVICE_AGENT_S5_REPORT.md)

### 4. service 为什么在旧任务上退步？

新增工具与提示改变了模型路径，保留工具名也不能保持行为等价。service 会用逐日遥测代替月记录、输出整份报告而忽略字段限制、混用部件资料；固定业务日期还与旧题“执行月”冲突。G5 三集为 service 4/12、1/6、0/6，对照 legacy 11/12、5/6、6/6。工具选择与答案通过分开统计，不能用调用成功掩盖最终交付错误。[报告 §6、§8](SERVICE_AGENT_S5_REPORT.md)

### 5. H5=0，为什么仍不算完全防住注入？

H5 只计载体诱导并执行的写入。本次诱导提议代理数也为 0，但最终回答的固定关键片段字面匹配为 react 4/12、plan 2/12；评审指出事实块展示载体文本共 7 条（react 4、plan 3），其中一条 plan 只有截断片段。执行边界与展示污染分别衡量，不能把前者的零事件宣传成模型完全免疫。[报告 §5](SERVICE_AGENT_S5_REPORT.md)

### 6. 如何减少评测作弊与事后挑选？

事先冻结题集、gold、种子、资料和实现身份；正式项各跑一次，异常与未执行仍在计划分母；每题独立数据库，谨慎用户只确认匹配提议；结果绑定 SHA256，先锁盲评分再揭盲。旧任务回归明确标“已见”。S3-E 曾获准重开冻结，另 6 道 dev 未重跑，不拼接成完整新成绩；holdout/legacy 基础设施中断经授权整集重跑并保留原目录。[报告 §2–3、§6、§9–10](SERVICE_AGENT_S5_REPORT.md)

### 7. 盲评有多独立？

这是 Claude 助手辅助、隐藏标签的评审；评审方参与过 gold 审核，不是独立专家评审。时间戳、工具轨迹、业务日期可能暴露模式或工具集；目录曾放过 key 与 comparison，评审方记录称未打开。评分锁定与哈希减少事后修改，但不能消除知情偏差或材料隔离不足。[报告 §9](SERVICE_AGENT_S5_REPORT.md)

### 8. 内容、忠实度、覆盖率与提议指标有什么区别？

内容分评价逐轮交付是否完整，忠实度检查是否有证据支持；覆盖率按 required_points 计，提议精确率/召回率同时要求工具和参数正确。test/plan 提议精确率虽为 17/17，全轮任务仍仅 12/30。卡片正确，仍可能漏答、编造或把待确认说成已完成。[报告 §3–5、§8](SERVICE_AGENT_S5_REPORT.md)

### 9. 小样本、超时和成本怎样解释？

test 每模式 30 案例、37 计划用户轮，注入每模式 12 例，且每项只跑一次，不能作显著性或生产可靠性结论。test/plan 有一轮未执行，p95 只用 36 个可观察时延，不填零。G5 service V2A05 超时、空回答与未执行仍计失败，不能剔除。串行加载状态与工具路径都影响延迟，不将 p95 差值单独归因于规划算法。[报告 §3–4、§6、§9](SERVICE_AGENT_S5_REPORT.md)

### 10. 下一步会怎样改？

先修确认前的完成声明、事实块的低信任文本展示、字段限定和月度/逐日数据源路由；让时间指代与固定业务日期显式区分，减少无效参数与重规划。之后重新登记实现和评测方案，冻结独立新题并做重复运行、改善评审隔离；较大模型的格式能力和成本作为消融假设验证。本阶段只展示现状，不改默认配置，不以已经见过的题代替新评测。[报告 §8–9、§11](SERVICE_AGENT_S5_REPORT.md)
