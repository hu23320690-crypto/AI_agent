# qwen3:4b 与 gemma4:12b 同题对照报告

日期：2026-10-22。分支 `eval/gemma4-12b-comparison`。两套已见回归题集（generalization_v1、holdout_v2，各 40 题），同一台机器、同一代码、同一检索索引，只替换聊天模型。环境、token 计数修复与运行方法见 [对照说明](../artifacts/gemma4_comparison/README.md)。

## 结论

**在答案质量上，gemma4:12b 好于 qwen3:4b，差距集中在知识问答的忠实度；Agent 任务两者持平。**

- 知识题严格通过：qwen3:4b **40/56**，gemma4:12b **48/56**。配对看，只有 gemma 通过 10 题、只有 qwen 通过 2 题。
- 差距主要不是“答错”，而是 qwen 更常加入本次资料不支持的内容，或把相邻条目的做法套到所问问题上：知识与资料不足题中，qwen 有 10 个回答忠实度不通过，gemma 有 2 个；内容不完整（分数低于 2）两者相近，qwen 9 个、gemma 7 个。
- 资料不足题：qwen 11/12，gemma 12/12，两者都没有编造所问数值。
- Agent 全轮任务：两者都是 11/12，失败的是同一题（G1A05）。本项目的报表查询与知识引用多由程序确定性生成，Agent 层几乎不区分两个模型。
- 速度：单次知识问答 gemma 较慢（中位数 2.3–3.2 秒，对 1.5–1.6 秒）；Agent 每轮 gemma 反而较快（中位数 13–18 秒，对 17–23 秒），尾部时延也更小。

## Agent 层为何持平

24 个 Agent 案例中，报表查询的最终回答由确定性渲染生成，维护条目常走生产校验的原文引用，两模型输出大多逐字相同；差别只在检索词改写与是否多调用 `get_user_id` 等，不影响结果。模型真正起作用的是长历史回忆轮与少数 RAG 总结轮，两者表现一致，G1A05 第二轮都没能遵守回忆出的“分章节说明”要求。

知识层同理有 7 题（G1K03、G1K06、G1K07、G1N05、V2K03、V2K19、V2N03）走程序校验引用或固定拒答，没有调用模型，两者逐字相同且都通过。

## 评审方法

- 每题按各题集冻结的 SCORING.md 判内容分（0/1/2）与忠实度。忠实度只认该次实际送入模型的证据、有效工具结果和会话历史。
- 两模型答案按题配对、以 X/Y 呈现，顺序按固定种子随机；对照键存放在仓库外，评分写入 `blind_scores.jsonl` 并记录 SHA256 锁后才揭盲。揭盲后评分逐条绑定结果 `result_sha256`，再由 `evaluation.report` 汇总。
- 忠实度判得较严：加入本次输入没有的理由或数值、把其他条目的处理套用到所问情形、丢掉数值的适用前提，都记为不忠实，即使内容本身听起来合理。这一口径对两模型一致，但会放大“回答更长、补充更多”的一方的失败数。

## 限制

- **评审者不独立**：评分由 Claude 助手完成。同一助手搭建了本次环境与计数器，并在冒烟测试中见过 3 题输出；两模型回答风格不同（gemma 更简短、qwen 更常附加说明），标签隐藏不能完全防止识别。这不是独立真人或领域专家盲评。
- **已见题**：两套题此前都用于修复，属于已见回归，不代表未见泛化能力。
- **单次运行**：每个模型每套题只跑一次，temperature 0，未测量重复波动。
- **上下文窗口**：两模型同为 8192 token；同一文本 gemma 约多用 7% token，未做补偿。
- **历史对照**：仓库中 qwen3:4b 在较早代码上由另一评审团队给出的成绩为 generalization 20/28、6/6、4/6，holdout 22/28、6/6、6/6；本次 qwen 重跑为 19/28、6/6、5/6 与 21/28、5/6、6/6，量级一致。两者代码与评审者不同，不作直接比较。
